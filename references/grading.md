# 批改规程

## 基本原则

- 批改的是**推理链**，不只是最终答案。答案对但过程跳步 → 标出来（考场会扣分）；答案错但方法对 → 给方法分。
- 每处批注都要**可执行**：指出哪一行、错在哪、怎么改。不要只打叉。
- 用户写对了的地方**不必逐行表扬**，但**关键判据写对了要点明**（"这里能想到先判断被积函数的奇偶性，是这题的关键"）。

## 部分给分

按步骤给分，明确告知"这步值几分、你丢在哪"：

| 步骤类型 | 常见分值占比 | 判据 |
|---|---|---|
| 识别/建式 | 15–20% | 建模、换元、写出正确表达式 |
| 方法选择 | 15–20% | 选对方法并说明适用条件 |
| 计算 | 40–50% | 每步正确性，符号/系数错误单独标 |
| 结论 | 10–15% | 收敛性判定、特解、取值范围等 |
| 规范 | 5–10% | 定义域、分类讨论完备性、答语完整 |

判定"方法选错"和"计算错"要分开记——前者要重学，后者只需要练准确性。

## 转写风险（读手写或用户打字时）

用户的转写**经常与意图不符**，不要把它当真实解答的一部分去批。遇到下列情况先问清：

- 符号歧义：`x` 与 `×`、`l` 与 `1`、`u` 与 `n`、`∂` 与 `d`、下标粘连。
- 括号层级不清：`e^2x+1` 是 `e^(2x)+1` 还是 `e^(2x+1)`。
- 上下限写反、积分变量与上下限字母冲突。
- 用户打字漏了分母/根号。

处理方式：**先复述一遍你读到的式子**（"我读到的是 ∫₀¹ x·e^(x²) dx，对吗？"），确认后再批。复述这一步比批错再返工便宜得多。

## "无法判定"的判定与输出

出现以下情况时，**不要猜**，直接输出无法判定：

- 关键步骤被裁切、遮挡、模糊。
- 图像整体不清到无法读到式子层级。
- 用户文字描述与图片内容明显矛盾（这时先问哪个是对的）。

输出格式：

```
无法判定：第 3 行的等号右侧被裁掉了，我看不到你后面怎么处理的。
麻烦只重拍/补打第 3 行那一小段（从 "∫ ... =" 开始到这一行结束）。
```

**必须给出具体重拍意见**（哪一行、拍哪一段）。笼统说"看不清，重拍"会让用户重拍三次还是不行。

## 常见批注写法（可直接套）

| 场景 | 批注 |
|---|---|
| 方法选择错 | "这里用洛必达要三次，泰勒一次就出来了。判据是分母有 x²，展开到二阶即可。下次看到'多项式分母 + 超越函数'先想展开。" |
| 适用条件漏 | "洛必达要求 0/0 或 ∞/∞，你这里代入是 1/0，条件不满足。先判断型再动手。" |
| 计算符号错 | "系数：arctan 的导数是 1/(1+x²)，你写成 1/(1−x²)。这是公式记忆问题，建议单独抄一遍导数表。" |
| 分类讨论不全 | "x>0 的情况你做了，x=0 和 x<0 还没讨论。范围题先列清定义域再分段。" |
| 丢绝对值 | "ln 里的表达式要加绝对值，这题 x 可以取负。积分结果里带 ln 就要先看定义域。" |
| 答案对但跳步 | "结果对，但中间'由单调有界得极限存在'这一步是这题给分点，考场上要写出来。你直接写结果可能拿不到那 3 分。" |

## 批改输出结构

```
【判定】正确 / 部分正确（约 X 分，满分 Y）/ 错误 / 无法判定
【错在哪一步】具体到行
【属于哪类】方法选错 / 概念不清 / 计算失误 / 前提遗漏 / 规范问题
【改正】这步应该怎么写
【下次的信号】看到什么就想起这条
```

**不要**在批改里夹带整题重新讲解——讲解放到用户问、或明确走②的时候。

## 批完之后的强制动作

1. 引导用户走**答案对照**四问（见 `references/teaching-protocol.md`）。
2. 把错题行写进 `records/questions.md`（字段见 `references/error-tracking.md`）。
3. 若同一`题型家族`本次已错 ≥2 次 → 停止出同类新题，回到概念或方法讲解重练。
